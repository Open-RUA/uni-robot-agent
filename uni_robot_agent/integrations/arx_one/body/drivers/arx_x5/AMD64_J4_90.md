# AMD64 J4 ±90° variant (default)

Profile `x5_2025_amd64_j4_90` widens joint 4 of both type 2 arms from the vendor library's
±1.29 rad to ±90°, the range in the ARX documentation. It is an RUA modification of the vendor
library, not a vendor release. It is the default: `dependencies.lock.json` pins the modified
library and `deploy/configs/host.example.json` uses this profile. The official library and profile
`x5_2025_amd64_type2` remain available through `dependencies.multiarch.lock.json` and
`deploy/configs/host.type2.example.json`.

## Coupled identities

| Item | Value |
| --- | --- |
| Official AMD64 library SHA-256 | `d07d53d14da17f0a1db2753e3339f9e4c055dad72df613c811b9692c4bede85c` |
| Modified AMD64 library SHA-256 | `ec4a7e7f2528797c6e9fcf1b30e773165be81b8d8130ed28c00510fd651e67a7` |
| X5 2025 model SHA-256 | `7c5381e59b6c00d19feaca88526c9b89aa46bbd34bef7b0f7a26f8858f822368` |
| Library variant | `rua_arx_amd64_j4_90_v1` |

The library stores the J4 lower and upper bounds as two doubles at file offsets `0x1BF328` and
`0x1BF358`; the constructor loads them into the bound arrays that both `stateEndControl` and
`statePositionControl` use. `dependencies.py` checks the whole input hash and the original
constants, changes only those two constants to ±π/2 and checks the whole output hash. It never
loads the library. Other joints, the EEF workspace, tracking protection, IK continuity checks
and the clipping code are unchanged.

## Building and switching

Build with the default lock as described in [DEPLOYMENT.md](../../../DEPLOYMENT.md#23-fetch-the-cache-and-build-the-runtime);
the native build compiles the controller against the modified library. For the official
library, pass `--dependency-lock body/drivers/dependencies.multiarch.lock.json` and use
profile `x5_2025_amd64_type2`.

The library, the compiled controller, the Body profile in `host.json` and the expected vendor
metadata in `environment.json` change together; replacing only the library is not a switch.
To move an existing type 2 configuration to this variant:

```bash
python -m uni_robot_agent.integrations.arx_one.body.drivers.arx_x5.stage_j4_90 \
  --host /path/to/host.json --environment /path/to/environment.json --output /path/to/new-dir
```

It keeps the input bytes under `original/` and writes `j4-90/` copies with both arm profiles,
the environment joint bounds and the expected vendor metadata updated. It rejects unknown
baseline profiles, bounds and hashes and never overwrites a directory. Nothing is deployed.

Recorded paths that the official bounds rejected were replayed against the new bounds with the
same IK preflight; this is a geometric check, not a physical or collision test.
